# 4̅2̅9̅ — Anti-429 для ChatGPT

Расширение Chrome (MV3), которое не даёт ChatGPT выбить вас за лимит при работе со многими вкладками, показывает, насколько вы близки к лимиту, и помогает найти и «усыпить» вкладки, которые крутят цикл опроса. Название: **429 с верхней чертой = «НЕ 429»**.

Неофициальное. Лимит не обходит — только растягивает запросы во времени и не показывает странице ошибку, пока блок идёт.

## Установка (1 минута)

1. Chrome → `chrome://extensions` → включить **Режим разработчика**.
2. **Загрузить распакованное расширение** → папка `extension/` из этого репозитория.
3. Закрепить значок (пазл → булавка). После установки **обновить вкладки ChatGPT** (F5), чтобы защита встала в страницы.

## Что показывает значок

| Значок | Смысл |
|---|---|
| зелёная точка, число `0–49` | загрузка порога в % (запросов за 10 с к порогу), всё спокойно |
| жёлтая, `50–79` | подходим к порогу |
| оранжевая, `80–99` | почти предел |
| красная, `38s` | **блок идёт**: сколько секунд осталось (по `Retry-After`), запросы удерживаются |
| серая, пусто | нет вкладок ChatGPT |

Лимитов четыре, они считаются **отдельно** (у ChatGPT это разные ручки):
**История чата** `conversations/<id>` (на ней падает «Could not load…») · **История (старый)** `conversation/<id>` · **Статус потока** `stream_status`/`resume` (цикл опроса) · **Список чатов** `conversations`.
Цвет значка и число — по самому загруженному из четырёх. Подробности — в подсказке при наведении и во всплывающем окне.

> Пороги со знаком `~` — **предположение** (4/4/6/8 запросов за 10 с), пока не пойман реальный 429. После первого 429 расширение запоминает, сколько запросов сервер принял в окне, и ужимает pacing под это число; через 30 тихих минут порог по шагу возвращается к исходному.

## Что делает защита страниц

* **Общий pacing на все вкладки.** Запросы истории/статуса/списка проходят через общую очередь (`navigator.locks` + общий журнал в `localStorage`): не больше 75% порога за окно. 20 вкладок, открытые разом, не устроят штурм.
* **429 не доходит до страницы.** При 429 запрос удерживается, общий cooldown берётся из `Retry-After` (иначе 2→4→8→15→30→45→60 с), после паузы запрос повторяется через ту же очередь. Только если ответа нет 5 минут, 429 всё-таки возвращается странице, и ставится 3-минутный cooldown.
* **Только безопасные GET.** POST (`resume`, `batch`, `init`) расширение не трогает и не повторяет.
* Выключатель: во всплывающем окне, «Защита страниц включена».

## Диспетчер вкладок

* **Таблица вкладок ChatGPT**: запросов в минуту, обращения к истории/потоку, МБ за 10 мин, 429, «⏸ держу N» (запросы, ждущие своей очереди), метка **«цикл?»** (≥4 запросов истории или ≥5 опросов потока за минуту, либо ≥100 МБ за 10 мин).
* **Сбросить** — `chrome.tabs.discard`: Chrome выгружает содержимое вкладки, сама вкладка остаётся в ряду и перезагрузится по клику (как при нехватке памяти). Есть «Сбросить „дёргающие“» и «Сбросить фоновые». Активные вкладки не трогаются. **Неотправленный черновик во вкладке может пропасть.**
* **Сессия**: «Сохранить открытые чаты» запоминает список вкладок; «Восстановить» открывает их **по одной с паузой** (по умолчанию 12 с), а не пачкой.
* **Окно нужного размера.** Всплывающее окно у значка Chrome жёстко ограничено по высоте (~600 px) и не растягивается. Поэтому в шапке есть три кнопки: **◧ слева** и **◨ справа** (отдельное окно, прижатое к краю экрана на всю высоту; границы можно двигать, размер и положение запоминаются, повторное нажатие переставляет то же окно) и **▮ панель** (боковая панель Chrome на всю высоту). Какой стороной стоит сама боковая панель, решает Chrome (Настройки → Внешний вид → Положение боковой панели): расширение этого переключить не может, в настройках есть кнопка, открывающая нужную страницу.
* Нужна встроенная альтернатива без расширения: `chrome://discards` (список вкладок + Discard) и `Shift+Esc` (колонка Network).

## Восстановление после `resume`-404 (v0.2)

Страница при переподключении к ответу шлёт `POST /backend-api/f/conversation/resume`. Если сервер отвечает 404, клиент уходит в цикл опроса `stream_status` и перекачивает историю (в публичных HAR: 46 раз за 10 минут, ~590 МБ). Расширение вмешивается **только** если: 404 пришёл в течение 30 с после `stream_status = IS_STREAMING`; за ~1,2 с (до ~6 с, если страница сама грузит историю) не пришёл «естественный» сигнал (WebSocket «ход завершён» или успех истории); эту беседу не восстанавливает другая вкладка (`navigator.locks`). Тогда запрос повторяется максимум с двумя другими смещениями, и странице отдаётся первый ответ, который **действительно** является `text/event-stream` с признаками протокола (пустой поток, JSON и поток только с ошибкой отвергаются). Выключатель: `cfg.recovery`.

## Защита вашей работы

* Мост страницы (`bridge.js`) сообщает **только флаги**: есть ли неотправленный черновик в поле ввода и идёт ли генерация (сам текст не читается и не отправляется).
* Метки во вкладке: **✎ черновик**, **⏵ идёт ответ**, **↻ N** (сколько раз восстановлен поток), **без защиты**.
* Массовые «Сбросить „дёргающие“» и «Сбросить фоновые» **пропускают** такие вкладки и пишут, сколько пропущено. Принудительно можно сбросить только отдельной кнопкой с подтверждением. Активную вкладку не сбросить никак.
* **«Защитить открытые вкладки»**: расширение само подключает защиту к вкладкам, открытым до установки (`chrome.scripting`), чтобы не нажимать F5 на двадцати вкладках сразу (это тот самый штурм). Делается автоматически при установке.

## Приоритеты и автолечение (v0.4)

Страница ChatGPT сама перезапрашивает историю открытого чата примерно **каждые ~50 секунд**, в том числе в фоновых вкладках. При 30–40 вкладках этого достаточно, чтобы лимит не остывал вообще, даже если вы ничего не делаете. Поэтому:

* **Фоновые вкладки не грузят историю**, пока вы на них не переключитесь (они всё равно не на виду). Видимая вкладка получает слот первой. Если окно Chrome перекрыто другим окном, Chrome считает все его вкладки скрытыми, и история ждёт, пока вы вернёте окно на передний план.
* **После блока уходит одна пробная попытка**, остальные вкладки ждут её итог, а не просыпаются разом и не перезапускают штрафной таймер сервера.
* **`Retry-After` сервера берётся как есть** (раньше он растягивался собственной экспоненциальной паузой). Уровень отказа растёт один раз на эпизод, а не на каждый ответ.
* **Автолечение.** Если странице всё же вернули ошибку загрузки (429/5xx), расширение запоминает вкладку (в окне метка «⚠ не загрузилась») и, когда лимит спокоен, нажимает **родную кнопку «Try again»**. Только внутри блока с текстом ошибки (кнопка «Try again» у ответа модели не затрагивается), по одной вкладке за раз (не чаще раза в 15 с), активная первой, с нарастающими паузами между попытками на одной вкладке и не больше четырёх попыток. «Спокойно» значит: нет блока, нет 429 за последние 30 с и в данный момент никто не грузит историю. Для 404/403 (удалённый чат, нет доступа) лечение не запускается. Есть кнопка «Повторить» для ручного запуска и выключатель в настройках.
* **Обновление без перезагрузки вкладок.** У каждой версии защиты свой флаг и ключ настройки; предыдущая версия, уже работающая в открытой вкладке (снять её нельзя), получает команду «пропускай напрямую», а новая подключается поверх.

* **Самообновление (v0.4.2).** Chrome не перечитывает папку распакованного расширения сам. Раз в полминуты расширение читает свой `manifest.json` с диска и, если версия там новее запущенной, перезапускает себя (не чаще раза в 10 минут, чтобы не зациклиться; выключатель `cfg.autoReload`). Первое такое обновление нужно один раз сделать вручную (↻ на `chrome://extensions`), дальше оно идёт само.

## Чего здесь нет (честно)

* **Пороги со знаком `~` остаются предположением**, пока не пойман реальный 429. Узнать истинный лимит OpenAI заранее можно только нагрузкой на аккаунт, а именно она нас и ломает, поэтому расширение учится на настоящих 429 и ужимает pacing под них.
* Я не проверял расширение на вашем аккаунте под реальной нагрузкой: тесты идут на локальном мок-бэкенде.
* Позднее подключённая (инжектированная) защита работает, только если страница вызывает `window.fetch` динамически; если приложение закэшировало `fetch` раньше, такая вкладка останется без защиты до перезагрузки (метка «без защиты» это покажет).
* Первые запросы после первой установки идут с порогами по умолчанию: настройки из `chrome.storage` попадают в страницу асинхронно.
* Объём трафика берётся из `Content-Length` (сжатый размер), для чанков он неизвестен.
* Детектор черновика/генерации опирается на селекторы ChatGPT (`#prompt-textarea`, кнопка Stop); при смене вёрстки метки могут пропасть, тогда защита от сброса становится слабее.

## Безопасность

`permissions`: `storage`, `webRequest` (только наблюдение, без блокировки), `alarms`, `scripting` (только чтобы подключить свои же файлы к уже открытым вкладкам ChatGPT); `host_permissions`: только `https://chatgpt.com/*`. Нет внешних адресов, куки, `eval`, удалённого кода. Тексты чатов расширение не читает и не хранит; названия вкладок вставляются в окно через `textContent`.

## Тесты

```
npm test              # 35 юнит-тестов: классификация, pacing, обучение порога, canDiscard, guard.js и recovery.js в песочнице (2 «вкладки»)
npm run test:browser  # реальный Chrome (временный профиль), мок-бэкенд: защита выкл. → 8 из 12 запросов получают 429; вкл. → 0
npm run test:e2e      # сквозной (30 проверок): инжекция в вкладку, открытую до установки, обучение порога, светофор, бейдж, цикл,
                      # discard, защита черновика, resume-404, пошаговое восстановление сессии, окно слева/справа, боковая панель
```
E2E и browser-тест запускают **отдельный** Chrome с временным профилем (ваш профиль не трогается) и убивают только собственный процесс.

## Структура

`extension/shared.js` — чистая логика (классификация, окна, пороги) · `guard.js` — перехватчик `fetch` (MAIN-мир) · `bridge.js` — мост storage↔страница · `background.js` — наблюдение, обучение, светофор, действия · `popup.*` — интерфейс.

`recovery.js` — восстановление после `resume`-404 (MAIN-мир). Идея перехватчика и восстановления вдохновлена MIT-расширением ChatGPT Conversation Availability Guard; код написан заново, см. `THIRD_PARTY_NOTICES.md`.
